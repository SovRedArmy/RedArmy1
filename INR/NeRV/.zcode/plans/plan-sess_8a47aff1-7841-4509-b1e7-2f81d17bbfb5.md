# 修正版决定性实验：码率重叠的 UAR 放大复现 vs ctrl500（预算阶梯校准，不追"论文预算"）

## 更正记录
- 撤回"论文预算=2400 GPU时"的说法：论文未给 HiNeRV epoch 数；data_multiple(×10)使代码 epoch 是论文语义的 ~100 倍；按论文语义全文 ≈31 GPU 时，可行。
- 已有预算对齐运行（I20/P6 代码epoch）各模型末段 PSNR 平坦（25.0~25.7）——该配置在此预算量级已收敛，瓶颈在模型规模/码率档而非时长。

## 实验设计

**UAR 侧（2 个码率点 + 预算阶梯）**：
- HiNeRV、GOP6、GOM=5（5 个独立组 → 5 卡并行，需给仓库打 3 行 --group-only 补丁）
- 模型规模 ms=0.9M 与 ms=1.8M（预计 bpp ~0.07 / ~0.13，与 ctrl500-S 的 0.1032 形成重叠区间）
- 预算 I=60/P=24 代码 epoch（现有匹配运行的 3 倍；若较 20/6 档 PSNR 提升 <0.3 dB 则视为收敛，若仍爬升则追加一档 I=180/P=72 做敏感性）
- 每配置 ≈25 GPU 时 ÷ 5 卡 ≈ 5h 墙钟；两配置共 ≈10h 墙钟、50 GPU 时

**单模型侧（零新算力）**：现有 ctrl500 S/M/L 锚点（31.82@0.1032 / 35.45@0.2035 / 38.85@0.4062）

**判定**：
- UAR 三点（0.022 现有点 + 0.07 + 0.13）vs ctrl500 三点，重叠区间 0.10~0.13 bpp 算 BD-rate
- UAR 侧算力约为 ctrl500 单点的 8~12 倍——若单模型仍胜，结论在预算维度保守成立；若 UAR 胜，则修正结论为"UAR 优势随模型规模/预算显现，同预算下不成立"，两层都如实写入报告
- 预算阶梯数据同时回答"匹配运行的 25.3 dB 距收敛多远"，作为附录证据

## 实施步骤
1. UAR 仓库 3 行补丁：main.py 组循环加 --group-only 过滤（repro patch 注释）
2. 冒烟：ms=0.9、I=2/P=1、单组 ~10 分钟跑通
3. 启动 2 配置 × 5 组 = 10 进程，空闲 GPU 按 10GB 显存闸门分配，setsid 脱离会话，TMPDIR 指向 NFS
4. 第一配置出结果后做预算敏感性判断（是否追加第三档）
5. 终表：v4-E2 / ctrl500 / UAR(两档预算) 四曲线 + 重叠区间 BD-rate + 全系列最终结论（含本次 2400h 错误的更正记录）

## 成本
约 10h 墙钟、~50 GPU 时、3 行第三方补丁；GPU 被占时调度闸门自动排队。
